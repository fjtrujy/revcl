# VUC Type streaming tables and strict literal relocation addends

Date: 2026-10-12. Branch: `vuc`.

## Baseline preserved

The original canonical VUC 2004.1 ELF remains the only byte-exact oracle.
Historical GCC 3.3.3 (20040125) with GNU as 2.15 revalidated
**166/166 accepted function symbols, 11,314/11,314 text bytes**.
The separate accepted data gate revalidated **244/244 named initialized
data objects, 71,536/71,536 bytes**. Host tests now total **95 passing**.

These counts are *explicitly accepted records*, not a whole-binary
matching ratio. An exact linked executable still does **not** exist.

## Newly reconstructed `Type` streaming name tables (experimental source)

Two local static arrays in the original executable:

| Original named symbol | Address | Length | Verified source-generated bytes | Relocations |
| --- | --- | ---: | ---: | ---: |
| `_ZZrsRSiR4TypeE2tn` | `0x0807700c` | 28 | 28/28 | 7 |
| `_ZZlsRSo4TypeE2tn` | `0x08077b60` | 28 | 28/28 | 7 |

These arrays come from **ordinary C++ code** defining
`std::istream& operator>>(std::istream&,Type&)` and
`std::ostream& operator<<(std::ostream&,Type)`. Each has seven
`static const char *tn[]` pointers with type names in semantic order:

```cpp
{"error", "int", "bool", "float", "float4", "function", "void"}
```

The original pointer targets are not contiguous: `error` and
`function` are shared with other original compilation units.
Each original linked target was read independently from the
original **.data** and checked against the original string bytes
inside **.rodata**; no original address is embedded in the C++
source, and no byte buffer/assembly is synthesized as substitute output.

The compiled GCC 3.3 object places the seven strings at different
local offsets, using ordinary `R_386_32` section-symbol
relocations. The original ELF resolver must therefore map the
*individual verified source literal* to its pinned original absolute
address, not add the candidate's local string offset again.

The original matcher mistakenly did the latter and reported 22/28
for each array. After correcting that relocation-addend handling,
both strict original-data comparisons pass **28/28** with **7/7**
resolved and verified relocations.

**Critical acceptance distinction:** The two C++ operator function
bodies in `vuc/probes/type_stream_names_oct12.cpp` are *not* byte-exact
reconstructions of their original functions. They remain in
`vuc/probes/`, and the two data manifests are **not** added to
`exact_data_candidates.json`. Their **56 matched bytes** are
exploratory evidence only, not part of the accepted 71,536-byte data
suite. Once the `Type` stream operator bodies are reconstructed
exactly in a legitimate original-style source unit, these two
verified data tables can be considered for strict acceptance.

## Verifier correction and safety

`vuc/scripts/match_data.py` now accepts an explicit nonnegative
candidate-local section relocation offset. It verifies:

1. the referenced symbol is a defined `STT_SECTION`;
2. the exact expected null-terminated literal exists at that
   candidate-local offset;
3. the original linked literal address belongs to the declared,
   file-backed original section;
4. the original linked bytes match the same expected literal; and
5. the final pointer relocation uses that *authenticated original
   literal VA*, not a guessed section base plus the local offset.

All existing zero-offset cases remain valid. Negative offsets,
incorrect candidate strings and wrong original literal addresses
are rejected. Host tests cover both positive nonzero candidate
offsets and these rejection paths.

## Remaining named-data inventory

`vuc/scripts/data_gap_inventory.py` independently enumerates
original sized, named `STT_OBJECT` symbols in `.data`, `.rodata`
and `.bss`, then classifies by the explicitly accepted data manifest.
Its reproducible original-ELF findings:

| Scope | Symbol records |
| --- | ---: |
| All named, sized objects in the three sections | 334 |
| Strictly accepted original data objects | 244 |
| Remaining named objects in `.bss` | 66 |
| Remaining named objects in `.rodata` | 22 |
| Remaining named objects in `.data` | 2 |

The 22 unmatched `.rodata` records include the generated
parser/lexer automaton tables (e.g. `yypact`, `yytable`,
`yycheck`, `yy_ec`) and two original compiler-generated
`__PRETTY_FUNCTION__` strings. They require grounded source/generator
recovery; copying numerical arrays or original machine bytes into
the candidate is not an acceptable reconstruction.

`.bss` is allocated zero-initialized memory with no file-backed
bytes. Its 66 records are **not** added to the existing initialized
data byte coverage merely because their original names and sizes
are known. Unnamed literals and section/linker layout also remain
outside this named-symbol inventory.

## Negative code-probe evidence

Two additional source-date compiler sweeps found no newly
byte-exact functions:

- `evaluate_csu_init_align_oct12.py` tested 360 pairs of
  original-date GCC C compiler options for loop, branch and
  label alignment; the 84-byte `__libc_csu_init` remains
  unverified. The compiler's source CFG/prologue does not match
  the original.
- `evaluate_global_wrapper_extra_oct12.py` tested 48 variants
  each for `matchStack`, `exportModule`, `script_debug`
  and `currFileName`, including `-fno-zero-initialized-in-bss`.
  These functions remain non-exact. No initializer is promoted.
- The compiler-generated instruction arena `__tcf_1` is still
  45/46, with a final pop-register difference after 21 flag
  checks and multiple ordinary C++ source forms; both
  historical December 2003 and January 2004 compilers retain
  this difference.

None of these tests inserts inline assembly or attempts
post-compilation byte patching.

## Reproduction

On the Mac host:

```sh
python3 -m unittest discover -s vuc/tests -q
python3 vuc/scripts/data_gap_inventory.py --summary-only
```

In the existing Linux VM:

```sh
r=/path/to/revcl/vuc
cc=/tmp/vuc-binutils215/g++-jan25-as215
$cc -O2 -frename-registers -c "$r/probes/type_stream_names_oct12.cpp" \
  -o /tmp/vuc-binutils215/type-names-oct12.o
for mode in input output; do
  python3 "$r/scripts/match_data.py" \
    --object /tmp/vuc-binutils215/type-names-oct12.o \
    --config "$r/config/type_stream_${mode}_names_oct12_probe.json"
done
python3 "$r/scripts/match_data_candidates.py" --compiler "$cc" \
  --out /tmp/vuc-binutils215/oct12-data-verified-244
```

The two provisional arrays pass individually, and the accepted
244-object gate remains **unchanged**. Whole-ELF byte equality
remains the mandatory, unachieved final goal.
