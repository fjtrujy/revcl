# VUC TypeConvert reconstruction and bounded source-unit controls

Date: 2026-10-13, branch `vuc`.
Historical compiler: GCC 3.3.3 (2004-01-25 prerelease), GNU as 2.15,
executed in the existing `revcl-oracle` VM. The original VUC executable
remains read-only inside the SHA-pinned upstream ZIP.

## New exact VUC application function

`Value::TypeConvert(Value const&, Value const&, Value&, Value&)`, original
`0x0806f7d0`, **220/220 original machine-code bytes**, **no relocations**
or literal-section references. Source:
`vuc/src/ValueTypeConvert.cpp`. Accepted candidate:
`vuc/config/value_type_convert_exact_oct13.json`.

Accepted historical command:

```sh
R=/path/to/revcl/vuc
limactl shell revcl-oracle -- /bin/sh -c '
  C=/tmp/vuc-binutils215/g++-jan25-as215
  R=/path/to/revcl/vuc
  "$C" -O2 -frename-registers -falign-jumps=1 \
    -c "$R/src/ValueTypeConvert.cpp" \
    -o /tmp/vuc-binutils215/valuetypeconvert-exact.o
  python3 "$R/scripts/match_probe.py" \
    --object /tmp/vuc-binutils215/valuetypeconvert-exact.o \
    --config "$R/config/value_type_convert_exact_oct13.json"
'
```

The original function starts with **two 32-byte Value object copies**,
including all type/flag/scalar/vector fields, and then compares the
original input types. The reconstructed C++ uses real Value assignment,
not hand-written copies or instruction templates. This produces the
correct initial load/store and register-allocation sequence.

For differing types, the original dispatch allows the integer/bool
representations (types 1/2) to mix, coerces them to type 1, and allows
mixing with a scalar float (type 3) by converting the integer payload
to a float using the compiler-generated x87 `fild`/`fstp` pair.
Unsupported combinations return false.

The source-level breakthrough was **nested C++ switch control flow with
one shared failure return**, not a compiler flag guess or synthetic
register control:

- Initial equivalent `if` chain: 223 generated bytes with jump
  alignment 1; original function is 220 bytes.
- Nested-switch with early separate false returns: original 220-byte
  length, **184/220** matching bytes, but the generated false-return
  epilogue used ECX plus an extra move to EAX.
- Authentic nested cases using `break` for unsupported inner types
  and a **single `return false;` at the end**:
  **220/220** exact, including the original common EAX epilogue and
  alignment NOPs.

Reproducible source-level scripts:

- `vuc/probes/evaluate_value_type_convert_structures_oct13.py`: nested
  switch, range checks, compound predicates, and original-length
  controls across `-falign-jumps` options. The first original-length
  match was 184/220.
- `vuc/probes/evaluate_value_type_convert_false_exits_oct13.py`: six
  natural outer-case orders and default/break layouts all reproduce
  **220/220** under `-O2 -frename-registers -falign-jumps=1`.
  Two `if`-structured alternatives were smaller and rejected.

All byte-exact results were compiled from genuine C++ source with the
historical toolchain and compared against the original named symbol.
No inline assembly, manually chosen register constraints, instruction
patching, arbitrary NOPs, invented relocated addresses, or binary
rewrites were employed. Multiple ordinary lexical orders match; this
does **not** establish the original author's exact source spelling.

## Other controls from the same batch

### MLTempString actual source-unit neighbors

`evaluate_mltemp_consecutive_unit_oct13.py` checks ordinary formatted
constructor, default constructor and `Set()` definitions, including
plausible original ABI return types and three normal local-expression
forms, preserving their original ELF order. It does not recover an
exact `Set()`. Its best standalone-length variant reached **105/117**
versus a previously preserved **111/117** isolated source hypothesis.
The pre-existing exactly accepted C1 constructors remain unchanged.

`evaluate_mltemp_data_prefix_oct13.py` adds the **real**
`MLTempStringData::FormatString()` and an experimental
`VFormatString()` implementation ahead of those constructors. The
best original-length `Set()` score recovers **111/117**, not 117/117.
The translation unit's extra original-character-string literals require
additional source-unit literal mapping before it can authenticate the
constructor/data region; this is **not** a proof of full source-unit
identity and must remain experimental.

### Instruction and Value arithmetic controls

`evaluate_instruction_real_prefix_oct13.py` inserts genuine
InstructionList methods before the original ToString/arena allocator/
static-cleanup sequence, with period compiler flags. The arena cleanup
remains **45/46**, differing by its last dead scratch-register POP,
while ToString remains **9/9 exact** in all normal configurations.
The attempted partial `AddLineComment` comparisons in this unit
do not have a complete original literal-section map and are **not**
promoted.

`evaluate_value_plus_probability_oct13.py` tests genuine
`__builtin_expect` branch weighting and case-branch hypotheses under
ordinary jump alignment options. Original-length addition candidates
remain at **172/219**, and there is no replacement for the existing
`Value::operator*()` exact C++ source or its real subtraction predecessor.

### VFormatString initial semantic source

`vuc/probes/ml_temp_vformat.cpp` has a 238-byte original target and
genuine string-formatting/arena recovery hypotheses, but the existing
partial probe's literal section still does **not** map faithfully to
the original binary; no original-size acceptance is claimed. The
canonical original string addresses must be independently verified
before using this method for exact acceptance.
